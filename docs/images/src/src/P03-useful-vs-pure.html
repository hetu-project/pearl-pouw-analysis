不做 AI、只挖矿，反而更赚钱

想边做 AI 推理边挖矿，门槛很高；只挖矿，门槛很低。H100 实测：做了推理，同一张卡的挖矿收益最好不到一半，在线服务时只有几个百分点。

离线 = 几百个请求同时提交、GPU 一直满载的最好情况；在线 = 请求陆续到达，GPU 空闲时不挖矿。"只挖矿"用 Pearl 自己的挖矿算子测得 318 TMAC/s，第三方软件更快，真实差距更大。电脑仿真估算 44–61%（含 70B），与实测相符。

BPearl 为什么这么设计？

算法原理决定人不够技术不支持工程实现问题
  • 协议不补偿有用矿工：奖励只按刮了多少彩票算，协议又分不出谁在做有用功（问题 1）。论文认为也不需要补偿：理论上有用矿工几乎不多花成本。
  • "几乎不吃亏"只在理论上成立：那是矩阵无限大时的结论。实测单次挖矿乘法要慢 87%–1846%；纯矿工能合法地省掉几乎全部额外工作，有用矿工没得选。
  • 挖矿内核只做了 H100/H200 版本：协议本身不限硬件，但官方边推理边挖的计算库只为 Hopper 架构编译。

C对我们 PoCW 的启发

  • 不能存在"不做有用功也能拿奖励"的路径：没有真实需求、没被验收的计算一分都拿不到。
  • 奖励按完成的有用任务计，去噪声、交付结果本身就是任务的一部分。
  • 协议不能把有用工作绑定到某种显卡、某套内核或某个专用模型。
