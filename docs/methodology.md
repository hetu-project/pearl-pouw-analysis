# 研究方法

## 1. 研究对象与版本

- Pearl 源码：`pearl-research-labs/pearl` @ `156ef9a8eb9dc7c74fab8c502598b8b53d4be7b1`（主网当前使用的 int7 方案，证书 V3）。
- FP8 方案：远程分支 `origin/fp8-scheme`，撰写时未在任何网络启用。
- 本仓库所有代码位置（`文件:行号`）均以上述版本为准。

## 2. 流程

1. **研究**：按组件阅读源码、论文和白皮书，写成研究笔记（`docs/notes/`）。每个结论标注依据：代码（文件与行号）、提交（commit hash）、实验（脚本与输出）、外部资料（链接与日期）。
2. **整理疑点**：研究中发现的可疑之处先只记录、不下结论，最后统一去重归类。
3. **逐条分析**：每条疑点分析到明确结论：
   - **成立**：问题确实存在；
   - **部分成立**：存在，但影响或可利用性有限；
   - **不成立（已排除）**：分析后排除，必须写明排除理由；
   - **待实测**：需要特定硬件（如 GPU）才能确定，附实验方案。
4. **复现**：对成立的问题，尽可能提供 benchmark（`benchmarks/`），任何人都可以在固定版本的 Pearl 上重跑。

## 3. 问题报告格式

每个问题一个文件（`docs/problems/`），包含：

1. **问题是什么**：一两句话说清楚；
2. **原来的算法是什么**：相关的挖矿、验证流程，附代码位置；
3. **怎么验证的**：实验环境、参数、测试组、检查步骤；
4. **Benchmark（实验结果）**：数据表与原始日志位置；
5. **会影响什么**：具体、可量化的影响；
6. **对我们的启发**：对 PoCW 设计的要求；
7. **怎么复现**：命令。

## 4. 严重程度

| 等级 | 含义 |
|---|---|
| 致命 | 协议的核心承诺不成立（如"有用"或"工作量不可伪造"），或可直接导致资金损失、链停止 |
| 严重 | 可被利用获得 10% 以上的不当收益，或显著削弱安全性、去中心化 |
| 中等 | 有实际影响，但可以缓解，或只影响部分场景 |
| 轻微 | 工程瑕疵、文档不一致，没有直接利用路径 |

## 5. 原则

- 只在本机和 Pearl 源码副本上实验，不在任何真实网络上测试。
- 理论上存在但实际不可利用的问题，与可利用的问题分开写。
- 涉及正在运行的网络、且有可利用细节的问题，先通过 Pearl 的安全渠道（见其仓库的 `SECURITY.md`）通知，再公开细节。
- "首次指出"均指在有限的网页与文献检索范围内未见公开报道。
